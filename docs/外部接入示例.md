# 外部系统接入 audit-service 指南

> **本指南面向：需要从其他服务调用 audit-service 做维修清单 / 修箱照片识别的接入方**
>
> 适用版本：v3.8-GG 起

---

## 1. 接入方式总览

| 场景 | 推荐方式 | 接口 |
| --- | --- | --- |
| 提交识别任务 | `POST /api/v1/audits` | 见 §2 |
| 轮询获取进度 | `GET /api/v1/audits/{task_id}` | 见 §3 |
| 拉取最终报告（含照片 ID 映射） | `GET /api/v1/audits/{task_id}/report` | 见 §4 |
| 想用回调通知 | `POST /api/v1/audits` 时填 `callback_url` | 见 §5 |

> 说明：当前推荐 **轮询模式** 接入。每 3-5 秒查一次状态即可，单任务典型 30-90s 完成。

---

## 2. 提交识别任务 — `POST /api/v1/audits`

### 2.1 接口

- **URL**：`http://cd124615069w.vicp.fun:25740/api/v1/audits`
- **Method**：`POST`
- **Content-Type**：`multipart/form-data`
- **返回**：HTTP 202 + JSON `{task_id, status, created_at, photo_id_list, photo_mappings}`

### 2.2 请求参数

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `manifest_image` | File | 是 | 维修清单图片（jpg/png/webp，≤10 MB） |
| `photos` | File[] | 是 | 修箱照片，1-30 张 |
| `photosIds` | String[] | 是（新接入方） | 客户业务照片 ID，与 photos 按顺序一一对应；同名字段重复提交 |
| `callback_url` | String | 否 | 完成后回调地址（详见 §5） |
| `metadata` | String(JSON) | 否 | 透传字段，原样回传，可放订单号等业务字段 |

### 2.3 curl 示例

```bash
curl -X POST http://cd124615069w.vicp.fun:25740/api/v1/audits \
  -F "manifest_image=@清单图.jpg" \
  -F "photos=@修箱照片1.jpg" \
  -F "photosIds=COMPANY_PHOTO_001" \
  -F "photos=@修箱照片2.jpg" \
  -F "photosIds=COMPANY_PHOTO_002" \
  -F 'metadata={"order_no":"BK-2024-001","container_no":"TGBU1234567"}'
```

返回：
```json
{
  "task_id": "aud_a1b2c3d4e5f6",
  "status": "pending",
  "created_at": "2026-08-15T03:33:21Z",
  "photo_id_list": ["ph_xxx1", "ph_xxx2"],
  "photo_mappings": [
    {"photosId": "COMPANY_PHOTO_001", "photo_id": "ph_xxx1", "seq": 1, "filename": "修箱照片1.jpg"},
    {"photosId": "COMPANY_PHOTO_002", "photo_id": "ph_xxx2", "seq": 2, "filename": "修箱照片2.jpg"}
  ]
}
```

### 2.4 Python 示例（requests）

```python
import requests

url = "http://cd124615069w.vicp.fun:25740/api/v1/audits"

files = [
    ("manifest_image", ("manifest.jpg", open("清单图.jpg", "rb"), "image/jpeg")),
    ("photos", ("photo1.jpg", open("修箱照片1.jpg", "rb"), "image/jpeg")),
    ("photos", ("photo2.jpg", open("修箱照片2.jpg", "rb"), "image/jpeg")),
]
data = {
    "photosIds": ["COMPANY_PHOTO_001", "COMPANY_PHOTO_002"],
    "metadata": '{"order_no":"BK-2024-001","container_no":"TGBU1234567"}'
}

resp = requests.post(url, files=files, data=data, timeout=30)
resp.raise_for_status()
result = resp.json()
task_id = result["task_id"]  # 拿这个去轮询
```

## 3. 轮询进度 — `GET /api/v1/audits/{task_id}`

### 3.1 接口

- **URL**：`http://cd124615069w.vicp.fun:25740/api/v1/audits/{task_id}`
- **Method**：`GET`
- **返回**：JSON `task` 对象

### 3.2 返回字段

```json
{
  "task_id": "aud_a1b2c3d4e5f6",
  "status": "succeeded",
  "current_stage": "p6",
  "progress": {
    "stage": "10/10",
    "detail": "报告编译完成"
  },
  "metadata": {"order_no": "BK-2024-001"},  // 原样回传
  "container_number": "TGBU1234567",
  "error": null,
  "photos": [
    {"photosId": "COMPANY_PHOTO_001", "photo_id": "ph_xxx1", "seq": 1, "filename": "photo1.jpg"}
  ],
  "created_at": "2026-08-15T03:33:21Z",
  "updated_at": "2026-08-15T03:35:14Z"
}
```

### 3.3 轮询代码

```python
import time, requests

task_id = "aud_a1b2c3d4e5f6"
url = f"http://cd124615069w.vicp.fun:25740/api/v1/audits/{task_id}"

while True:
    r = requests.get(url, timeout=10).json()
    status = r["status"]
    print(f"[{task_id}] {status} @ {r.get('current_stage')}")
    if status in ("succeeded", "failed", "cancelled"):
        break
    time.sleep(5)  # 5 秒轮询一次

if r["status"] != "succeeded":
    raise RuntimeError(f"识别失败: {r.get('error')}")
```

## 4. 拉取最终报告 — `GET /api/v1/audits/{task_id}/report`

### 4.1 接口

- **URL**：`http://cd124615069w.vicp.fun:25740/api/v1/audits/{task_id}/report`
- **Method**：`GET`
- **返回**：JSON 完整报告（含 OCR 结果与匹配结果）

### 4.2 报告结构（关键字段）

```json
{
  "task_id": "aud_a1b2c3d4e5f6",
  "container_number": "TGBU1234567",
  "container_recognition": {
    "source": "photo",
    "confidence": 0.9,
    "source_photo": {
      "photosId": "COMPANY_PHOTO_001",
      "photo_id": "ph_xxx1",
      "seq": 1,
      "filename": "photo1.jpg"
    }
  },
  "repair_move": 35.0,
  "photo_mappings": [
    {
      "photosId": "COMPANY_PHOTO_001",
      "photo_id": "ph_xxx1",
      "seq": 1,
      "filename": "photo1.jpg",
      "photo_url": "/api/v1/audits/aud_a1b2c3d4e5f6/photos/ph_xxx1/image"
    }
  ],
  "item_verifications": [
    {
      "item_no": 1,
      "description": "Straighten side panel",
      "total": 100.0,
      "verification_status": "verified",
      "matched_photos_detail": [
        {
          "photosId": "COMPANY_PHOTO_001",
          "photo_id": "ph_xxx1",
          "photo_name": "photo1.jpg",
          "photo_url": "/api/v1/audits/aud_a1b2c3d4e5f6/photos/ph_xxx1/image",
          "confidence": 0.95
        }
      ]
    }
  ]
}
```

> 渲染页面时优先使用 `photosId` 回关客户自己的照片记录；`photo_id` 是本系统内部 ID。`item_verifications[].total` 是单项 Total，顶层 `repair_move` 是整箱 RepairMove。没有证据照片的 Item 不会返回 `verified`。

### 4.3 Python 示例

```python
r = requests.get(f"http://cd124615069w.vicp.fun:25740/api/v1/audits/{task_id}/report", timeout=10)
r.raise_for_status()
report = r.json()

for item in report["item_verifications"]:
    print(f"[{item['item_no']}] {item['description']} -> {item['verification_status']}")
```

## 5. （可选）回调推送 — `callback_url`

如果不想轮询，提交任务时填 `callback_url`，audit-service 成功完成后会 POST 一条通知，接入方再根据 `report_url` 拉取完整 JSON 报告。

### 5.1 用法

提交任务时附带：

```bash
-F "callback_url=http://你的服务:端口/callback"
```

### 5.2 回调 body 结构

```json
{
  "task_id": "aud_a1b2c3d4e5f6",
  "event": "task.succeeded",
  "status": "succeeded",
  "report_url": "/api/v1/audits/aud_a1b2c3d4e5f6/report"
}
```

调用方式：`POST`，`Content-Type: application/json`。如已配置 `WEBHOOK_SECRET`，请求头同时包含 `X-Audit-Signature: sha256=<HMAC>`。发送失败按服务端配置重试。

### 5.3 你只需写一个 HTTP 接收端点

最小 Flask 示例（接收方）：

```python
from flask import Flask, request, jsonify
app = Flask(__name__)

@app.post("/callback")
def callback():
    data = request.json
    task_id = data.get("task_id")
    status = data.get("status")
    # 写库 / 推业务系统
    print(f"task {task_id} -> {status}")
    return jsonify({"ok": True})

app.run(host="0.0.0.0", port=9000)
```

## 6. 部署与网络

| 项 | 建议 |
| --- | --- |
| 协议 | HTTP（内网） |
| audit-service 对外地址 | `http://cd124615069w.vicp.fun:25740` |
| 超时 | `POST /api/v1/audits` 30s；`GET /report` 10s |
| 限流 | 单 IP 默认 60 req/min，按需调 nginx 层 |

生产环境另有 AI 算力保护：待处理队列默认最多 10 个任务、每天默认最多接收
20 个任务。达到任一限制时 `POST /api/v1/audits` 返回 HTTP 429，且不会生成
任务或保存照片。`detail.code=AI_AUDIT_BUSY` 表示队列繁忙，
`detail.code=AI_AUDIT_DAILY_LIMIT_REACHED` 表示当天额度已用完；调用方应显示
“审核忙碌中”，并依据 `Retry-After` 响应头稍后重试。

## 7. 常见问题

**Q1：上传图片有大小限制吗？**
- 单图 ≤ 10 MB，每任务 ≤ 30 张。改上限见 `config/dgx.yaml` → `upload`。

**Q2：失败了能重跑吗？**
- 重新 `POST /api/v1/audits` 提交一次新任务即可，旧任务的数据保留在库中可查询。

**Q3：metadata 字段会原样回传吗？**
- 任务创建时存的什么，`GET /api/v1/audits/{task_id}` 就返回什么。建议放 `order_no` / 外部 ID，便于关联。

**Q4：怎么只读数据库，不调识别？**
- audit-service 直接读 Postgres。如果你有运维权限，跳过 audit-service 用 SQL 直查 `manifest_items` 表也可以，但失去 OCR 调度的能力。
